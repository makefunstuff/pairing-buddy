# The video: a person in the second chair

A six-minute tour of everything pairing-buddy does, in seven chapters: getting started (install, `pair auth`, one
model, `pair doctor`, the roles), exploring code (the wrong turn, the search trail, the context card, crashes and
compiler errors, the exploration loop and `:Pair runs`, `Alt-?`, the held thought), tests (on save, the
regression, a green), notes and the blank page, handing over (with and without a test), the day around it (the
ledger, other agents, the debrief and the morning pick-up), and the rest in a montage (push-to-talk, earcons,
Scout's rc file and sandbox, several Neovims, Pair without herdr). It ends on the keys to remember. A one-minute
cut for X shows the three moments that matter most each day.

It plays in the [README](../../README.md) and on the [website](https://makefunstuff.github.io/pairing-buddy/#tutorial),
where the chapter buttons and each feature card jump into it.

The video is a [HyperFrames](https://hyperframes.heygen.com) composition: `index.html` (the tour) and `short.html`
(the cut for X) are generated by `build.mjs` from its scene lists, over real captures of the shipped plugin.

## What is real

- **The Neovim scenes** are the captures of [docs/captures](../captures/): the plugin, the daemon, its triggers, the
  Watcher's gate, the test runs, builds and runs, and what Neovim draws all run for real, on small Go and C
  projects. Only the models' words are scripted, through a stand-in OpenAI-compatible server, so every take says
  the same thing. `clips.sh` places them in the film's frame.
- **The setup scenes** (`capture/`): `install` runs the real `npm install -g github:makefunstuff/pairing-buddy` and
  `pair setup` in an empty sandbox home. `start` logs in with `pair auth` (with a made-up key, stored only in the
  sandbox), shows a one-model config and runs `pair doctor` against a stand-in local model
  ([local-model.mjs](capture/local-model.mjs)) that thinks when asked to.
- **Push-to-talk** needs whisper.cpp to record, so its few seconds in the montage come from the README's GIF of it.

## Make it again

Node.js 22+, FFmpeg, Go, a C compiler, clangd, bubblewrap, Neovim 0.11+, VHS 0.11 with ttyd, and an OpenRouter key
in `/tmp/openrouter.key` (or `$OPENROUTER_KEY_FILE`) for the voice, the music and the word timings. The key is read
at run time and never printed.

```sh
../captures/record.sh          # the Neovim scenes, into docs/captures/out/
capture/run.sh                 # clips/install.mp4 and clips/start.mp4 (or name one tape)
./clips.sh                     # the Neovim scenes into clips/, at the film's size
node tts.mjs [scene ...]       # audio/<scene>.mp3 from narration.json (existing files are kept unless named)
node words.mjs                 # words.json: when each word of the script is said, for the captions
node music.mjs                 # audio/music.mp3, the bed under the voice
node build.mjs                 # index.html, captions.vtt, chapters.json, chapters.vtt and frames/
node build.mjs short           # short.html and captions-short.vtt
npx hyperframes@0.8.205 render . --quality delivery --no-browser-gpu --output renders/final.mp4
npx hyperframes@0.8.205 render . -c short.html --quality delivery --no-browser-gpu --output renders/short.mp4
./finish.sh                    # the files people watch, see below
```

`finish.sh` writes `renders/pairing-buddy-tour.mp4` (for the README, under GitHub's 10 MB), the site's `hero.mp4`,
`hero.webm`, `hero-poster.jpg`, `hero.vtt` and `hero-chapters.vtt`, and `renders/pairing-buddy-x.mp4`, the cut for X.
The README plays the tour from a GitHub attachment (GitHub plays a video in a README only from its own
attachments, not from a file in the repository); for a new cut, drop the file into any comment box on github.com
and put the `user-attachments` link it gives in the README. The chapter times in the README and on the site come
from `chapters.json`.

`build.mjs` holds the scenes: their titles, which stretch of a capture each one plays and how fast, where the camera
zooms, the callouts (`marks`), the keys shown on screen, the montage's cards, and the chapters. Times are seconds
into a scene, or a word of the narration. Boxes are in the clips' pixels: `I()` takes terminal cells of the setup
scenes, `P()` a box in a Neovim capture's own 1400x840 pixels (an OCR of its screenshot in docs/captures/out gives
them). Change the script in `narration.json`, then run `tts.mjs` for that scene, `words.mjs` and `build.mjs`.

## Keeping it public

Every capture runs as a user whose home is a scratch folder under `/tmp`, with its own socket, so no personal path,
host or model name can show, and the running pairing-buddy service is never touched: the daemon gets a socket in
that folder, `capture/systemctl` stands in for `systemctl --user` during `pair setup`, and the shell the tapes type
into has no variable whose name holds KEY, TOKEN, SECRET or PASSWORD. The models are named `local-model`,
`your-model`, `watcher` and `partner`. Before a new video is published, OCR its frames and check them and the
file's metadata for usernames, home paths, hosts, IP addresses, ports and model names.
